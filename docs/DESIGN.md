# 初回試作の設計

## 核となる体験

「聴く → 仮に置く → つなぎを聴く → 発見する」。音楽理論の問題ではなく、短い旋律の行き先を自分で見つける遊びにする。ハーモニーカードの構造やルールを持ち込まず、独立した音の並べ替えとして設計した。

仮タイトルは「おとのつづき」。タイトルや外観より先に、音を聴いて試す流れの手応えを確かめる。落ち着いた紙色と緑色の同じカードを使い、すべての音を対等に扱う。音の波形・譜面・長さ・色分けは正解を視覚的に伝えてしまうため使わない。

## 曖昧さの扱い

音楽として成立する順序が一つしかないとは言えない。そこで勝利条件を「このオリジナルのお手本を再構成する」と定義した。お手本はいつでも明示操作で再生でき、正解の断片順を視覚表示しない。聴き比べが苦手でも、2つの断片から試して学べる。

曲は呼びかけ・上昇・山場・帰着の役割を持たせ、短い中でも続きに意味があるようにする。判定のためだけに機械的な音階を並べる構成を避ける。失敗時は正しい文字順を教えず、「高いところ」「長い終わりの音」など聴くポイントを伝える。

文字 A/B/C/D は同じセッション内の識別にのみ使う。空の盤面を開始する際の文字割り当ては偏らせず、2断片が必ず B→A になる抜け道を防いだ。シャッフルは解答そのものを避けるため、2断片では逆順になる。入門レベルは試す組み合わせ自体が少なく、音だけを強制するゲームではない。

## 段階と報酬

2 → 3 → 4 断片の3曲に絞る。各曲は約4.8秒、9.6秒、16秒。初回は短く試せ、最後の曲では小さな展開を聴ける。クリア済みの曲も自由に行き来できる。

試聴とお手本は旋律＋ベース。完成時は同じ旋律に柔らかい和音と細かい伴奏を加える。正解の通知だけで終わらず、自分がつないだものを一曲として聴くことが報酬になる。完成後の「並びを聴く」でも、この伴奏を聴ける。

## 操作と実装

- 本物の button 要素で、タップとキーボードに同じ操作を提供する。
- 選択→配置、既存配置同士の交換、未配置の音による置き換え、取り外しを用意する。
- 音声をユーザー操作で初めて作成する。次の再生、配置変更、シャッフル、曲変更は前の音を停止する。
- 再生準備の非同期処理には世代番号を持たせ、停止後に遅れて音が始まる競合を防ぐ。
- 音量とミュートは master gain に適用する。短い音の発音包絡で硬いクリックを抑える。
- visibilitychange と pagehide で発音を停止し、AudioContext を suspend する。復帰は明示再生を待つ。
- localStorage の形式と断片の整合性を検証する。壊れた状態や保存不可でも開始できる。
- 静的な HTML/CSS/ES modules と Web Audio で構成し、Pages のプロジェクト配下へ相対 URL で配信できる。

## 次の確認

mon が実際に試聴し、耳で順序を探すことが楽しいか、完成時の伴奏が気持ちよいか、3曲目が長すぎないかを確認する。自動 QA は操作と音声出力の動作確認であり、曲の魅力や初心者への難しさを人の代わりに評価したものではない。方向を確認してから曲や演出を増やし、公開設定へ進む。
